# work-to-skills

**버전 0.3.1** (2026-10-26) · [변경 내역](CHANGELOG.md) · MIT · [English](README.md) · **한국어**

내 Claude Code 사용 기록을 보고 **어느 업무 영역에 스킬을 만들면 좋을지** 알려 주는 Claude Code 플러그인입니다.

Claude를 오래 쓰다 보면 같은 일을 할 때마다 같은 말을 반복하게 됩니다. 예를 들어 숏폼 영상을 몇 주 만들다 보면 "실사 합성은 하지 마", "피드는 4:5로", "동작 없는 줌 컷은 다시" 같은 말을 날을 바꿔 계속 하게 되고, 결국 그걸 기획·생성·편집·검수 스킬로 묶게 됩니다. 이 플러그인은 그 지점을 **기록에서 먼저 찾아 줍니다.**

![샘플 리포트 (가짜 데이터)](https://raw.githubusercontent.com/Soulddgy/work-to-skills/assets/screenshot-ko.png)

## 리포트에 나오는 것

1. **업무 영역 스킬 후보** (핵심)
   - 같은 흐름을 여러 날 반복하고, 고쳐 가며 같은 규칙을 다시 말한 업무 영역
   - 영역마다: 작업 흐름, 쌓인 규칙(실제로 하신 말과 날짜), 이미 있는 스킬·CLAUDE.md·메모리, **스킬을 만든 뒤에도 다시 말한 규칙**, 제안하는 스킬 묶음, 그대로 붙여 넣으면 만들어 주는 **만들기 프롬프트**
   - 스킬이 이미 있으면 새로 만들지 않고 "무엇을 보강할지"를 제안합니다
2. **작은 자동화**: 빌드 후 복사, 커밋·푸시처럼 매번 따로 시키는 기계적인 단계를 명령·hook·스크립트로 묶는 후보
3. **지난번 대비**: 반복 요청이 늘었는지 줄었는지
4. 작업 유형, 반복 요청, `/insights` 막힌 지점, 주별 흐름, Claude가 실제로 돌린 명령, 날짜·프로젝트 분포, 긴 세션

리포트는 파일 하나로, 인터넷 없이 열립니다. 상단에서 한국어·영어를 바꿀 수 있고, 섹션과 블록은 접고 펼칠 수 있습니다(만들기 프롬프트는 펼친 채로 시작).

## `/insights` 와의 차이

| | `/insights` | work-to-skills |
|---|---|---|
| 세션 목표·결과·막힌 지점 | ✅ | `/insights` 결과를 가져와 씀 |
| 어느 업무 영역에 어떤 스킬을 만들지 | — | ✅ 규칙·흐름 근거와 만들기 프롬프트 |
| 이미 만든 스킬에 빠진 규칙 | — | ✅ 스킬 만든 날짜 이후 다시 말한 규칙 |
| 같은 요청을 몇 번, 며칠에 걸쳐 했는지 | — | ✅ |
| Claude가 실제로 돌린 명령 | 도구 이름만 | ✅ 명령 단위 |
| 리포트 언어 | 영어 | 한국어·영어 전환 |

## 설치

```text
/plugin marketplace add Soulddgy/work-to-skills
/plugin install work-to-skills@work-to-skills
```

필요한 것: Claude Code, Python 3.9 이상.

"막힌 지점" 섹션은 `/insights` 분석을 가져다 씁니다. 분석이 오래됐으면(마지막 실행이 일주일 넘게 지났거나 이번 기간 세션의 절반도 반영 안 됐으면) 리포트를 만들기 전에 **"`/insights` 를 먼저 돌려 주세요"** 하고 멈춥니다. `/insights` 는 사용자가 직접 입력해야만 실행되는 명령이라 스킬이 대신 돌릴 수 없습니다. 돌린 뒤 "계속"이라고 하면 이어서 만들고, "그냥 진행"이라고 하면 있는 데이터로 만듭니다.

## 사용법

평소 말투로 요청하면 됩니다.

- "어떤 업무에 스킬을 만들면 좋을지 찾아줘"
- "내가 Claude한테 계속 같은 말 하는 게 뭐야? 이미 만든 스킬에 빠진 것도"
- "my-app 만 놓고 10월 작업 패턴 분석해줘"
- "최근 2주를 그 전 2주랑 비교해서 반복이 줄었는지 보여줘"

결과는 `~/Documents/work-to-skills/` 에 생깁니다. 미리 보고 싶으면 [`examples/sample-report.ko.html`](examples/sample-report.ko.html) 을 내려받아 열어 보세요(가짜 데이터).

## 개인정보와 접근 범위

모든 처리는 내 컴퓨터 안에서만 합니다. 대화 기록에는 소스 코드나 사내 논의가 그대로 들어 있을 수 있어서, 스킬은 사용자가 직접 요청하기 전에는 리포트를 어디에도 올리지 않습니다.

| | |
|---|---|
| **읽는 것** | `~/.claude/projects/*/*.jsonl`(Claude Code 대화 기록)과 프로젝트별 메모리(`~/.claude/projects/*/memory/`), `~/.claude/usage-data/`(`/insights` 가 남긴 분석), 이미 만든 것을 확인하려고 `~/.claude/skills/`, 작업 폴더의 `.claude/skills/` 와 `CLAUDE.md`. 설정 파일이나 인증 정보 파일은 읽지 않습니다 |
| **쓰는 것** | `~/Documents/work-to-skills/`(리포트, 중간 데이터, 실행 기록) 또는 지정한 폴더만 |
| **실행하는 것** | 들어 있는 Python 스크립트 두 개(`extract.py`, `render.py`, 표준 라이브러리만)와 리포트를 여는 `open` / `xdg-open` / `start` |
| **네트워크** | 없음. 스크립트는 네트워크 요청을 하지 않고, 리포트도 인터넷에서 아무것도 불러오지 않습니다 |
| **Claude를 통해** | 요청을 분류하려고 Claude가 세션 안에서 요청 묶음을 읽습니다. 평소 파일을 읽어 달라고 할 때와 같은 방식입니다 |
| **하지 않는 것** | 스킬을 대신 만들기(만들기 프롬프트만 줍니다), hook·MCP 서버·패키지 설치, 설정 변경, 위 폴더 밖에 무언가를 남기는 일 |

## 알아둘 점

- **분류와 규칙은 Claude의 판단입니다.** 업무 영역, 작업 유형, "이건 규칙이다"라는 판단은 Claude가 문장을 읽고 정합니다. 숫자는 정확한 값보다 **크기와 순서**로 보세요.
- **기록은 기본 30일만 남습니다.** Claude Code는 `cleanupPeriodDays`(기본 30일)가 지난 대화 기록을 지웁니다. 더 긴 기간을 보고 싶으면 그 설정을 늘려 두세요.
- **작업 시간은 근무 시간이 아닙니다.** 대화 기록이 남아 있는 시간만 셉니다. 자리를 비운 시간은 빠지고, Claude가 혼자 오래 작업한 시간은 들어갑니다.
- **막힌 지점은 `/insights` 가 분석한 세션만 나옵니다.** 오래됐으면 스킬이 먼저 돌리라고 알려 주고, 리포트에도 적용 범위가 표시됩니다.
- **토큰을 꽤 씁니다.** Claude가 기록을 읽고 분류하기 때문에, 한 달치 한 프로젝트 기준으로 한 번에 약 15만~20만 토큰이 듭니다. 기간이나 프로젝트를 좁히면 줄어듭니다.
- **Claude Code가 업데이트되면 숫자가 틀어질 수 있습니다.** 기록 파일 형식이 바뀌면 일부가 빠지거나 잘못 셀 수 있습니다. 이상하면 이슈로 알려 주세요.
