# work-pattern-report

[English](README.md) · **한국어**

내 Claude Code 사용 기록을 세서 **자주 반복해서 시키는 일**을 로컬 HTML 리포트로 보여 주는 Claude Code 스킬입니다. 무엇을 자동화할지를 느낌이 아니라 횟수로 정하게 도와줍니다.

내장 명령 `/insights` 를 대체하지 않고 보완합니다. `/insights` 는 세션마다 목표, 결과, 막힌 지점을 잘 설명해 줍니다. 이 스킬은 거기서 세지 않는 것들을 셉니다.

| | `/insights` | work-pattern-report |
|---|---|---|
| 세션 목표·결과·막힌 지점 | ✅ | `/insights` 결과를 그대로 씀 |
| 같은 요청을 몇 번, **며칠에 걸쳐** 했는지 | — | ✅ |
| Claude가 실제로 돌린 명령(`git commit`, `npm test`, `gradlew assemble*` 등) | 도구 이름 수준 | ✅ 명령 단위 |
| 횟수와 실제로 한 말을 근거로 단 자동화 후보 | 서술형 | ✅ |
| 후보마다 바로 만들 수 있는 설계: 실행 시점, 단계(자동·승인 필요), 만들 위치, 복사해서 쓰는 만들기 프롬프트 | — | ✅ |
| 이미 있는 스킬·hook과 겹치는지 확인 | — | ✅ |
| **자동화한 뒤 반복이 줄었는지** | — | ✅ 지난 실행과 비교 |
| 리포트 언어 | 영어 | 한국어·영어를 한 파일에, 전환 버튼 |

![샘플 리포트 (가짜 데이터)](docs/screenshot-ko.png)

*스크린샷은 [`examples/make_sample.py`](examples/make_sample.py) 로 만든 가짜 데이터입니다.*

## 설치

```text
/plugin marketplace add Soulddgy/work-pattern-report
/plugin install work-pattern-report@work-pattern-report
```

또는 `skills/work-pattern-report/` 폴더를 `~/.claude/skills/` 에 복사해도 됩니다.

필요한 것: Claude Code, Python 3.9 이상(표준 라이브러리만 사용). `/insights` 를 먼저 한 번 돌려 두면 좋지만 필수는 아닙니다. 없으면 막힌 지점 섹션 자리에 안내 문구가 나옵니다.

## 사용법

평소 말투로 요청하면 됩니다.

- "내가 무슨 작업 많이 하는지 보여주고 자동화할 만한 것도 뽑아줘"
- "지난주(10/19~10/25) 주간 회고 하게 정리해줘"
- "my-app 만 놓고 10월에 반복해서 시킨 일 위주로 분석해줘"
- "최근 2주를 그 전 2주랑 비교해서 반복이 줄었는지 보여줘"

리포트는 대화하는 언어로 열리고, 상단 목차 오른쪽의 한국어 / English 버튼으로 바꿀 수 있습니다. 파일은 `~/Documents/work-pattern-report/` 에 생깁니다.

```
report_<시작>_<끝>.html   리포트 (파일 하나, 인터넷 없이 열림)
data/<시작>_<끝>/         추출한 요청, 분류, 해석
history.json             실행마다의 반복 횟수 (지난번 대비 비교용)
```

## 동작 방식

1. **추출** (`scripts/extract.py`): `~/.claude/projects/*/*.jsonl` 에서 사람이 직접 입력한 메시지만 남깁니다. 서브에이전트 대화, 시스템 알림, `/compact` 뒤에 붙는 요약은 뺍니다. 그리고 다음을 붙입니다.
   - `~/.claude/usage-data/` 의 `/insights` 분석
   - 단위별로 쪼갠 Bash 명령
   - 활동이 기록된 5분 칸으로 계산한 추정 작업 시간
2. **분류**: Claude가 세션마다 작업 유형을 붙이고, 다른 날에도 다시 나온 요청에는 **반복 키**(예: `커밋·푸시`)를 붙입니다. 지난 실행의 키 이름을 그대로 써서 변화를 추적합니다.
3. **해석**: Claude가 자동화 후보를 씁니다. 후보마다 반복 키, 명령, `/insights` 마찰 유형을 연결해서 모든 주장에 숫자가 붙습니다. 후보마다 구체적인 설계도 붙습니다.
   - 언제 실행되나
   - 단계(**자동** / **승인 필요** 표시)
   - 결과물, 만들 위치, 사람이 남길 일
   - Claude Code에 붙여 넣으면 그대로 만들어 주는 만들기 프롬프트

   연결된 반복 횟수는 다음 실행 때 비교할 기준선이 됩니다. Claude가 쓰는 문장은 모두 한국어·영어 두 벌입니다.
4. **렌더** (`scripts/render.py`): HTML 파일 하나를 만들고, 외부 요청은 없습니다. 레이아웃은 신문 데이터 데스크 방식을 따랐습니다(The Economist 차트 스타일, 스위스 그리드, 터프티의 직접 라벨링).
   - 흰 바탕에 강조색은 빨강 하나
   - 직각 모서리, 번호 붙은 섹션
   - 상단 고정 목차
   - 밝은·어두운 테마

## 개인정보

모든 것이 내 컴퓨터 안에서만 처리됩니다. 스크립트는 로컬 파일을 읽고 로컬 파일을 쓸 뿐 네트워크를 쓰지 않습니다.

대화 기록에는 소스 코드, 비밀번호, 사내 논의가 그대로 들어 있을 수 있습니다. 그래서 스킬은 Claude에게 사용자가 명시적으로 요청하기 전에는 리포트를 어디에도 올리거나 게시하지 말고, 요청받아도 먼저 위험을 알리라고 지시합니다.

이 저장소 안에서 스킬을 돌리더라도 리포트와 데이터 폴더는 `.gitignore` 로 git에서 빠집니다.

## 한계

- 작업 유형과 반복 키는 Claude가 붙인 분류라서, 경계에 있는 요청은 옆 분류로 들어갈 수 있습니다.
- 작업 시간은 기록이 찍힌 5분 칸을 센 값입니다. 자리를 비운 시간은 빠지고, Claude가 혼자 오래 돈 시간은 들어갑니다. 근무 시간과는 다릅니다.
- `/insights` 는 세션 일부만 분석하고, 가장 최근 세션은 아직 분석하지 않았을 수 있습니다. 리포트에 적용 범위가 표시됩니다.
- Claude Code 버전에 따라 기록 형식이 바뀔 수 있습니다. 숫자가 이상하면 이슈로 알려 주세요.
